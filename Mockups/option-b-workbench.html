  3. Your expert column has one such case. NFLPlayByPlayData has two experts. Decide now whether that row takes the first value, or whether expert becomes a collection field later.

Needs a new API endpoint

  1. Bulk export at real scale. /api/search caps top at 25, so it cannot back an export of everything matching a facet set. This needs its own route that pages the index and streams CSV. Use $skip up to 100k documents, or a sorted key beyond that. Stream the response rather than building the file in memory, and apply the same facet filters server-side.
  2. Scope is a real decision. Selected rows is trivial and client-side. Everything matching the filters is the one people actually want and the one that needs the endpoint. This prototype exports whatever is on screen so the interaction is real.
  3. Governance worth settling first. A public, unauthenticated app that exports 900 rows of catalog metadata including owner names is a different risk profile from one returning 15 search results. Decide whether export requires sign-in even if search does not, and log every export next to the query in dbo.search_log.
  4. CSV hygiene is already handled here. Cells beginning = + - @ are prefixed with an apostrophe so Excel cannot execute them, and the file carries a UTF-8 BOM. Both matter when the export contains free-text descriptions.
